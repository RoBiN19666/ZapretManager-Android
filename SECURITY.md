# Безопасность

## Ключ подписи

До 2.0.0 ключ `keystore/zapretmanager.jks` и пароль были опубликованы в репозитории.
Это было осознанное, но ошибочное решение: любой мог подписать APK, который Android
принял бы как обновление. В 2.0.0 ключ считается скомпрометированным и заменён.

Сейчас:

* приватный ключ хранится только вне репозитория и в GitHub Actions Secrets;
* APK 2.0.0 подписан новым сертификатом
  `DB:AB:2D:4E:D5:B9:E5:0A:13:28:3D:F7:01:C3:4D:1A:60:40:D5:9A:29:11:79:D3:7B:13:44:AC:BA:55:35:C2`;
* из-за смены ключа APK 2.0.0 не ставится поверх 1.x: нужна разовая переустановка
  (экспорт backup → удаление → установка → импорт);
* старые релизы и теги удалены, старый ключ вычищен из истории Git. Полностью
  отозвать уже скачанные копии невозможно — не устанавливайте APK 1.x.

## Проверка обновлений

Перед установкой APK приложение проверяет:

1. SHA-256 из релиза (`*.apk.sha256`) — **обязателен**, иначе обновление отклоняется;
2. имя пакета (`io.github.robin19666.zapretmanager`);
3. непустые сертификаты и совпадение подписи с установленным приложением;
4. `versionCode` строго больше текущего;
5. все редиректы только по HTTPS; размер APK ограничен.

Репозиторий публичный, поэтому проверка релизов и загрузка APK идут без авторизации.
Токены не используются: все источники публичные.

Установка выполняется через `PackageInstaller` с системным подтверждением.

## Разрешения

| Разрешение | Зачем |
| --- | --- |
| `INTERNET`, `ACCESS_NETWORK_STATE`, `ACCESS_WIFI_STATE` | сеть, проверки, загрузки, определение Wi-Fi |
| `BIND_VPN_SERVICE` (в сервисе) | ускорение соединения через `VpnService` |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_SPECIAL_USE`, `POST_NOTIFICATIONS` | постоянные уведомления движков |
| `RECEIVE_BOOT_COMPLETED` | автозапуск по желанию пользователя |
| `REQUEST_INSTALL_PACKAGES` | самообновление |
| `QUERY_ALL_PACKAGES` | выбор приложений для раздельного туннелирования |
| `ACCESS_COARSE_LOCATION`, `ACCESS_FINE_LOCATION` | имя Wi-Fi для профилей сети (запрашивается по кнопке) |

Приложение не собирает телеметрию. Оно обращается к GitHub, Cloudflare, Telegram,
ByeByeDPI, Flowseal и — при явном запуске диагностики — к youtube.com/discord.com.
`allowBackup` выключен, поэтому настройки и MTProto-секрет не уходят в облачный backup.
`usesCleartextTraffic=false`; исключение — native WS/80 внутри Go-рантайма Telegram,
который не подчиняется NetworkSecurityPolicy.

## Сообщить о проблеме

Откройте issue в репозитории. Перед публикацией удалите из журнала секреты: MTProto-секрет,
приватные адреса серверов.
