# Безопасность

## Ключ подписи

`keystore/zapretmanager.jks` **публично доступен** вместе с паролем. Это сделано осознанно:
Android не позволяет обновлять приложение с другой подписью, поэтому без стабильного ключа
самообновление невозможно.

Следствия:

* ключ нельзя использовать ни для одного другого приложения;
* злоумышленник с доступом к репозиторию может выпустить обновление, которое пройдёт проверку
  подписи — доверяйте только релизам из этого репозитория и проверяйте SHA-256;
* если нужна приватная сборка — замените keystore, но тогда обновления потребуют переустановки.

## Проверка обновлений

Перед установкой APK приложение проверяет:

1. SHA-256 из релиза (`*.apk.sha256`), если он опубликован;
2. имя пакета (`io.github.robin19666.zapretmanager`);
3. сертификат подписи совпадает с установленным;
4. `versionCode` строго больше текущего.

Репозиторий публичный, поэтому проверка релизов и загрузка APK идут без авторизации.
Токены не используются: все источники публичные.

Установка выполняется через `PackageInstaller` с системным подтверждением.

## Разрешения

| Разрешение | Зачем |
| --- | --- |
| `INTERNET`, `ACCESS_NETWORK_STATE` | сеть, проверки и загрузки |
| `BIND_VPN_SERVICE` (в сервисе) | ускорение соединения через `VpnService` |
| `FOREGROUND_SERVICE*`, `POST_NOTIFICATIONS` | постоянные уведомления движков |
| `RECEIVE_BOOT_COMPLETED` | автозапуск по желанию пользователя |
| `REQUEST_INSTALL_PACKAGES` | самообновление |
| `QUERY_ALL_PACKAGES` | выбор приложений для раздельного туннелирования |

Приложение не собирает телеметрию и не отправляет данные наружу, кроме запросов к GitHub и
Cloudflare/Telegram, неускорениеимых для работы функций.

## Сообщить о проблеме

Откройте issue в репозитории. Перед публикацией удалите из журнала секреты: MTProto-секрет,
приватные адреса серверов.
