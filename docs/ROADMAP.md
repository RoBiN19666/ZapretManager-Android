# Планы и известные ограничения

## Что уже работает

* Ускорение соединения через `VpnService`: byedpi + tun2socks, 8 встроенных стратегий, список из ByeByeDPI,
  свои аргументы, раздельное туннелирование по приложениям.
* Telegram-прокси: локальный MTProto, маршруты `cf_proxy_ws` / `direct_ws` / `tcp_fallback`,
  Fake TLS, ссылки `tg://` / `t.me` / SOCKS5, автозапуск, плитка быстрых настроек.
* Проверка сервисов через SOCKS-порт byedpi.
* Обновления: APK из GitHub Releases (SHA-256 + versionCode), стратегии/сайты из
  ByeByeDPI, CF-домены из Flowseal/tg-ws-proxy, еженедельный bump сабмодулей в CI.
* Расписание работы обхода (окно времени, в том числе через полночь).
* Экспорт журнала в файл и отправка через «Поделиться».
* 98 JVM-тестов, включая UI-тесты Compose на Robolectric; гейт тестов и lint в CI.
* Документы: политика конфиденциальности, материалы для каталогов, инструкции сборки.

## Что стоит сделать дальше

1. **Проверка на реальном устройстве** (обязательный этап): установка APK, выдача VPN,
   проверка стратегий на мобильной сети и Wi-Fi, поведение при смене сети, работа плитки.
2. **Маршрут `awg_warp`** (AmneziaWG/WARP): рантайм его поддерживает, нужен UI профилей и
   provision-логика.
3. **Автопереключение при смене сети**: профили Wi-Fi/оператора уже работают, но наблюдатель
   сети живёт в основном процессе приложения. Для переключения при закрытом приложении нужен
   foreground-сервис наблюдателя (с уведомлением) — отдельная задача.
4. **Автозапуск ускорения после перезагрузки**: проверить ограничения FGS на Android 14/15 и,
   при невозможности, использовать `VpnService` в режиме always-on.
5. **Локализация**: сейчас интерфейс на русском, строки вынесены частично (в `strings.xml`
   пять записей, остальное — литералы в коде). Нужен полный `values/strings.xml` и `values-en`;
   выносить надо экран за экраном, иначе интерфейс окажется полупереведённым.
6. **Тулчейн и `targetSdk`**: AGP 8.6.1, Kotlin 2.0.20 и Compose BOM 2024.09 собраны и работают,
   но к концу 2026 `targetSdk 35` ниже требований Google Play (API 36). Переход на 36 включает
   принудительный edge-to-edge на Android 16, поэтому его нужно проверять на устройстве, а не
   только сборкой.

7. **Разбиение `SettingsScreen`** (~1150 строк, девять секций в одном файле): вынести секции
   в отдельные файлы и убрать общее состояние в отдельные ViewModel-и.

## Известные ограничения

* Приложение не является системным VPN: Telegram-прокси обрабатывает только трафик Telegram.
* После остановки ускорения процесс `:native` завершается — это требование byedpi, а не баг.
* Живость движков проверяется по локальным портам (раз в 5 секунд в UI-процессе): если
  система «усыпила» приложение целиком, проверка возобновится при следующем открытии.
* IPv6 в туннеле по умолчанию выключен: часть трафика может идти мимо.
* Репозиторий публичный: самообновление и компоненты проверяются без авторизации.
* Обновление APK проверяет совпадение подписи с установленным приложением (`PackageManager`);
  сборку с другой подписью приложение отклонит намеренно.
