# Планы и известные ограничения

## Что уже работает

* Обход DPI через `VpnService`: byedpi + tun2socks, 8 встроенных стратегий, список из ByeByeDPI,
  свои аргументы, раздельное туннелирование по приложениям.
* Telegram-прокси: локальный MTProto, маршруты `cf_proxy_ws` / `direct_ws` / `tcp_fallback`,
  Fake TLS, ссылки `tg://` / `t.me` / SOCKS5, автозапуск, плитка быстрых настроек.
* Проверка сервисов через SOCKS-порт byedpi.
* Обновления: APK из GitHub Releases (SHA-256 + подпись + versionCode), стратегии/сайты из
  ByeByeDPI, CF-домены из Flowseal/tg-ws-proxy, еженедельный bump сабмодулей в CI.

## Что стоит сделать дальше

1. **Проверка на реальном устройстве** (обязательный этап): установка APK, выдача VPN,
   проверка стратегий на мобильной сети и Wi-Fi, поведение при смене сети, работа плитки.
2. **Автоподбор стратегий**: прогнать список через SOCKS-порт, оценить по сервисам и сохранить
   лучшую — как «Тест стратегий» в десктопной версии.
3. **Маршрут `awg_warp`** (AmneziaWG/WARP): рантайм его поддерживает, нужен UI профилей и
   provision-логика.
4. **Перезапуск при смене сети**: `ConnectivityManager.NetworkCallback` → мягкий перезапуск
   движка без вмешательства пользователя.
5. **Автозапуск обхода после перезагрузки**: проверить ограничения FGS на Android 14/15 и,
   при необходимости, использовать `VpnService` в режиме always-on.
6. **Локализация**: сейчас интерфейс на русском, строки вынесены частично; полный `values-en`.

## Известные ограничения

* Приложение не является системным VPN: Telegram-прокси обрабатывает только трафик Telegram.
* После остановки обхода процесс `:native` завершается — это требование byedpi, а не баг.
* IPv6 в туннеле по умолчанию выключен: часть трафика может идти мимо.
* Репозиторий публичный: самообновление APK, стратегии и пул CF-доменов проверяются без токена.
  Токен в настройках нужен только для приватных форков и повышенного лимита GitHub API.
* Проверка подписи APK использует `PackageManager`; для сборок с другой подписью обновление
  отклоняется намеренно.
